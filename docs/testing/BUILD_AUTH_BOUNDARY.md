# 建置認證值與安全診斷

Vinext 會為各次建置產生伺服器端共用認證資料。revalidation bearer 用於框架快取重新驗證；preview bypass ID 用於框架預覽模式；prerender bearer 用於框架預先渲染入口。這些不是員工登入密碼，也不能據此取得員工 ADMIN 角色。preview signing／encryption 的生成名稱存在，不代表已確認其編譯常值或曝光。權限判斷仍以實際框架消費端與站台設定為準，未執行攻擊或遠端有效性測試。

先前一次產物比較把原始差異視窗放入工具輸出，確實包含舊、新隔離建置的前三類認證值。該臨時比較沒有保存可重跑的原始函式來源；原因依實際作者、工具紀錄及已固定的生成／消費端查明，不杜撰來源雜湊。曝光位置包含伺服器 isr-cache chunk、server/index.js、兩份 vinext-server.json 及工具輸出的 oldWindow／newWindow。報告不複製認證原值或個別原值雜湊，也不送往外部檢查服務。

舊工作窗停止只證明當時站台已收尾，不能證明這些值被撤銷或已到期。若重新啟用相同編譯產物，認證情境可能仍相同。受影響舊編譯包與診斷證據只作私有保存，不分發或部署，不宣稱已撤回工具歷史。若未來需要使用該編譯情境，必須先提出具體重新發行／輪替與部署範圍；本次不修改原員工帳密、session secret 或正式環境。

## 正常建置入口的防護

`npm run build` 保留原 Vinext CLI、local-network-preload、環境及非零結束狀態。已整合的修正將子程序 stdout／stderr 改為每個通道最多 8 MiB 的記憶體捕獲，只輸出固定欄位的結果、警告／錯誤數量與允許的診斷分類，不轉送或保存原始行、例外訊息、stack、差異視窗或認證值。超限、捕獲失敗、缺少或重複建置後檢查結果均失敗；不是隱藏失敗後宣告成功。中斷只傳給自己建立的子程序並等待其實際關閉，Windows 訊號不視為 POSIX 正常關閉保證。

建置後檢查使用實際 server define 與兩份 prerender manifest 作短期記憶體比對，檢查該次全部宣告的 client 產物；已知認證值進入 client 則失敗。伺服器端所需認證保留，不以每程序隨機值破壞跨 isolate 一致性。這是已知生成值的邊界檢查，並非通用秘密掃描器，也不構成編譯伺服器產物可以公開分發的批准。

後續產物比較使用 `createSafeDiagnostics().difference`，只回報允許的相對位置、大小、是否改變與差異起點。禁止把實際 server define、manifest 內文、原始產物視窗或未處理的例外序列化到工具、日誌或交付文件。

## 驗證與交付界線

兩個離線測試分別驗證認證邊界／診斷，以及正常入口／記憶體捕獲／檢查掛鉤／訊號所有權。使用合成值的正反控制不等於實際建置通過：必須另有最後固定來源、乾淨依賴、正常入口實際建置的結束狀態、client 檢查及產物清單，並核對實際 SOURCE-ONLY ZIP。

SOURCE-ONLY 僅交付固定來源與必要版本說明，不含 dist、編譯 server 認證情境、node_modules、Local 資料庫或私有登入檔。它是分發邊界，不能代替診斷原因修正、實際建置或員工冷安裝驗證。最新已整合／實測狀態由 [HANDOFF](../../HANDOFF.md) 的唯一索引定位；候選及未測不得寫成 PASS。
