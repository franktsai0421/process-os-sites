## 範圍及判定依據

依 [共用草稿規格](../specs/current/SHARED_DRAFT.md)、[整份草稿規格](../specs/current/WHOLE_MODULE_DRAFT.md) 與實作交叉核對。2026-10-27 補充明確支持 V3「僅保存」保存現有共用草稿、「僅送審」送出最後成功保存快照；不應為了補按鈕而額外授予編輯。legacy 整份取代快照的 Save／Submit 仍須編輯，不能直接套用 V3 的放行條件。

保存／送審範圍是整個模組，包含其他頁籤、篩選外資料與其他人的已套用修改。線別／工序沿用 AB／C 共用草稿，不是獨立草稿。草稿、保存快照、送審固定案件、生效版本不可混為一談。

## 建議權限設定方式

保留原有查看、新增、編輯、刪除、保存、送審、撤回、核准、發回，先修正對應關係，不必重做整套角色。標籤建議：

- 編輯：開始草稿／套用修改；不代表保存或送審。
- 保存：保存整份已套用共用草稿，可獨立於編輯授權。
- 送審：送出最後成功保存版本，可獨立於編輯／保存授權。
- 刪除：刪除草稿中的資料，不是刪除歷史。
- 新增「還原歷史至草稿」：可改動整份內容，應獨立授權並檢查新增／刪除差異。
- 查看歷史可先沿用查看權限，不急著另加一格；只有確定需要限制敏感歷史時再拆分。

新增還原權限的既有角色與個別覆寫遷移須明列前後差異；不默認把 edit 擴充成新管理能力。保存／送審／核准前應顯示整份範圍、保存者與快照時間；授權與 pending／CAS／資料一致性限制應以不同原因說明，不能全部顯示「無權限」。
