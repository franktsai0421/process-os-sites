## 實作與風險

- 共用 bootstrap 原本依序等待多個已選定的 R2 物件。候選版沿用有界讀取器，在已授權的資料階段及最後的獨立身分重讀中，每批最多開始五個 GET。逐項讀取內文並驗證 SHA，保留既有 session、revision、投影及失敗處理。可重用身分記錄的中間階段沿用原機制。
- 例行檢查首頁先查啟用與版面，再讀完整資料。原本兩次查詢都解碼全站聚合，並在判斷是否需要前建立檢查來源。現在啟用查詢讀權限、開關及本模組；普通 GET 另外讀主資料與品質資料，只展開例行來源實際採用的已核准 FQC 版本。需要的版本或聚合損壞仍會失敗，可在修復後重讀。全頁仍保有例行文件、草稿、歷史及圖片引用。
- 影響包括全站目的地 GET、例行入口、例行送審，以及其他送審頁取得例行待審數時的普通 GET。資料模型、寫入及排程程式均無變更。

## 重現與判讀

在基準與候選的獨立 checkout 安裝鎖定依賴。兩邊使用候選版相同的兩支 benchmark 腳本，先設定該 checkout 的 `PROCESS_PROGRAM_COMMIT`，執行 `npm run build`，再以相同的 `CHROME_PATH` 及 `NAV_ROUNDS=5` 執行 `node scripts/benchmark-page-navigation.mjs`。也可在候選 checkout 用 `PROCESS_TEST_BUILD_DIR` 指定保存的基準 dist。handler 比對則各自在對應原始碼執行 `NAV_IO_MS=5 node scripts/benchmark-navigation-reads.cjs`。程式僅使用隔離 fixture。

例行與品質送審的中位數下降。品質送審再次進入的最慢值較高，製程編輯台、BOM、模具及部分品質頁也有持平或變慢的樣本。低延遲 loopback 放大影格排程與執行波動；這批數據不足以證明每頁都加速。實站尚待相同登入身分、資料量及可操作條件複測，5 秒門檻仍未驗收。

## 聚焦回歸

- PASS：原生同文件切頁測試包含重複點擊、不同目的地快速交錯、舊 GET 晚到、失敗保留來源、同身分撤銷、已保存重讀、未知回執避免重送，以及原圖檢視。
- PASS：bootstrap 27 個目的地回應對照、13 組身分與投影檢查；FQC 來源投影的正反例；例行權限、必要物件損壞／重試、歷史、全頁雙文件保存／送審／撤回及 CAS。
- BLOCKED：主測試站在新瀏覽器要求登入，無已授權的站內 session 或代表性業務快照。
- NOT_RUN：站點發布及發布後驗收。遠端 CI 請見 Draft PR。

## 交錯複測與慢樣本定位

以同一部雲端機器序列執行相鄰的基準與候選。奇數對先基準、偶數對先候選。每次重建隔離 worker、D1、R2、瀏覽器及 context，先開 dashboard，再按原順序首次及再次進入 20 個目的地。基準為 `8c94a77`，候選使用從 `f3be6d5` 乾淨建置的程式；兩版 server/index.js SHA-256 分別為 `2349d3b953942b4ea8d35df7d1aa53586757a62ab67b144400c9d6f03b6b220f` 和 `7f4ff1417c40a509a32289d163baa5390c3aa3a04dcb9b9c77ddbbe894248918`。

沿用原資料 12 對，加入實際可顯示的合成業務內容再量 12 對，對這批內容另做 4 對限速及 12 對影格診斷。共 3,200 次可操作切頁。各組獨立計算。原始逐對毫秒數可依頁面、版本及首次／再次切入重算。[下載逐對資料](main-navigation-pairs-20261118.csv)

擴充資料含兩個 BOM 主件、80 個零件位置，兩個線別各發送一個產品，製程編輯台有已採用版本、共享草稿、一個作業節點和五個工段範本，模具有 60 件及兩個版本。沿用五個品質模組各 40 筆、兩個歷史版本、40 個排程、1 個待審計畫及 1 張去重的合成 PNG。BOM 須出現可操作品號、模具須出現可開啟的設備、編輯台須出現指定的作業節點。建置中的模組、更多實際工單、未壓縮的獨立照片及大型畫布仍待實站驗證。

### 影格與長尾檢查

下表取擴充資料獨立再跑 12 對時各版的最慢樣本。API 聯集、ready generation 寫入時點及最長兩次影格觀察間隔會彼此重疊；總時間還須等頁面資料與控制項可用並經過下一影格。最長影格間隔含主執行緒工作及排程。

模具的長尾值得保留。擴充資料與影格診斷合計 24 對，首次中位／P90／最慢為 117.5／144／154 → 121.5／149／193 ms，逐對中位差 +5.5 ms，雙尾符號檢定 p = 0.839。193 ms 樣本的 bootstrap 耗時 123 ms，其中等待回應首位元組為 119 ms；模具 workflow 耗時 30 ms。兩次 GET 的順序和數量一致。品質送審的另一次首次極值也變長（494 → 531 ms），其 bootstrap 佔 118 ms，該組首次中位為 438 → 397 ms。

再以原生 worker、同一合成身分與擴充資料分開量模具 bootstrap，排除離開編輯台與畫面繪製。設定 `NAV_PROBE=tooling-bootstrap`，每對每版啟動新 worker，dashboard 就緒後依序請求 25 次，每次消耗完整 JSON 並核對身分及目的地。兩版各有 12 個首次樣本、288 個同 worker 再讀樣本。首次中位／最慢 33.9／41.9 → 32.5／41.9 ms；再讀中位／P95／最慢 23.6／30.6／119.3 → 22.1／28.7／45.9 ms。按獨立 worker 的再讀中位計算，12 個配對差的中位為 −0.5 ms，符號區間 [−4.7, +0.8]。候選的獨立端點未重現該筆 123 ms 延遲。

BOM、模具、編輯台三者的首次中位退步未在兩個擴充資料批次穩定重現。例行送審首次及品質送審再次的較慢極值也未在兩批重現。現有樣本仍容許小幅退步；模具的整頁極值有再現，但當時 bootstrap 的異常等待無法歸因於候選讀取排程。這次追加量測、資料與診斷，保留先前已驗證的兩條 GET 修改。測試資料建置時曾抓到缺少 BOM 核准資料與範本圖片，已補上可操作 BOM 與隔離 PNG；上述統計只包含完整成功的配對。
