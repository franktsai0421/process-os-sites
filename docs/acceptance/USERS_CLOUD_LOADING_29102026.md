# 使用者與權限：第二輪載入優化（CLOUD 29102026）

本輪因使用者要求再縮短進頁等待而追加，沿用 `cloud/users-permissions-29102026`，未混入其他任務。100ms = 0.1 秒；原先 195ms 是簡化模組 fixture，不是完整網站載入。本報告改量完整編譯應用從頁面導航開始，到最新帳號資料已顯示、導航 ready、兩次動畫畫格完成。

## 修改與邊界

- `app/api/user-access/route.ts`：同一請求內，沒有個別覆寫的啟用帳號共用其角色計算；Frank、個別設定、舊式獨立權限及停用帳號仍依完整政策分別計算。可編輯矩陣以角色／本人／主要管理員／DEMO 的不同條件分開重用。角色人數單次累計。140 個使用者投影逐格對照未重用的既有政策通過。
- 新增 `public/process/user-access-initial-read.js`：只在既有 bootstrap 完成登入／目的頁驗證後，對 users 目的頁提前發出一次 GET，與既有腳本初始化重疊。UI 採用前仍檢查帳號、generation、目的頁及 revision；身分或頁面失效就丟棄／中止。沒有跨請求授權快取，其他目的頁不發出這個請求。
- `public/process/user-access.js`／CSS：超過 50 人的清單分頁，每頁最多 50 人；搜尋與角色／啟停篩選涵蓋全部帳號，變更條件回第一頁。角色編輯的可編輯設定由每格重算改為一次計算。
- 共用 `public/process/index.html`：僅註冊上述初載腳本及本模組資源版號。其他目的頁仍會下載這個小腳本，但條件不符即結束、不讀帳號 API；其他頁面的額外資源載入耗時尚未量測。沒有修改 bootstrap、身分驗證、導航、共用讀寫、送審或其他業務程式；DB／R2 schema 與儲存格式不變。

沒有省略後端授權、密碼驗證、保存讀回、CAS 或歷史保護。列表 API 仍回傳所有已授權帳號，分頁只減少 DOM 列數；本輪沒有宣稱已實作伺服器分頁或減少資料庫資料量。

## 完整頁面前後計時

比較基準分支 HEAD `7af150a`（程式與已編譯 `3be743ed2abfa3b475df95eac1b33d1136be497d` 相同，差別為文件）；候選程式 `91942a677fb3fc5d912437b65bd8f495972d70ea`。結果 JSON 記錄實際 bundle 與來源 SHA-256。

相同 Node 24／Chromium、1440×1000、Miniflare 非持久 D1／R2、相同 4／200 個合成帳號、loopback 無網路節流。每組 5 次，前後循序執行，測量時沒有同時跑 build／其他測試。每次使用新瀏覽器 context：先以正常帳號 API 登入，再量冷 HTTP cache 首次開頁及同 context 暖 cache 重新整理。登入輸入與密碼驗證不計入此表；伺服器／OS 不保證完全冷啟動。資料及頁面確定可操作才停止計時。

| 帳號數／操作 | 修改前中位數／最慢 ms | 修改後中位數／最慢 ms | 中位數變化 |

| 4 人／首次完整頁面 | 721.0／763.5 | 668.1／790.1 | 約快 7.3% |

4 人首次最慢值反而增加，改善幅度小，不能宣稱穩定加速或 SLA。200 人原先一次畫出 200 列，候選只畫第一頁 50 列，API 及搜尋仍涵蓋 200 人；這是明確的 UI 分頁變更，不是漏載帳號。尚未另訂完整頁面 ≤100ms 目標；本輪也沒有達到這個數字。

網路收據顯示每次初載只有 1 次 user-access GET；候選的 GET 開始時間早於 assets ready，證明重疊工作而非省略請求。中間只做計算重用／重疊、尚未分頁的版本也量過：200 人首次 806.8ms、暖重整 459.5ms（各 5 次）；完整原始收據保留，沒有用中間版本取代最終版本。

這不是既有測試站的速度。其部署版本仍未知、沒有發布本輪修改，也沒有對既有資料庫做寫入。完整網站切到其他模組再回來，本輪未取得成功測速：基準測試嘗試導航到 dashboard 時仍停留 users，逾時；未修改該跨模組流程，也未將暖 cache 重整冒稱同頁導航回來。
