# IQC explicit Save conflict choices — local integration

Base: `b06394ce0065849733399423afd2d906761d69c1`. This local integration reuses IQC candidate `13ef792` and combines its shared-client lease with FQC. Each actual module keeps its own draft and original recovery scope.

Form completion remains local until explicit Save; filters retain input and module departure drops only unsent input without a prompt. Scheduled draft synchronization/reads are removed. Save compares the original basis, local intent and current complete shared draft. Independent changes survive; one bilingual Mine / Theirs / Cancel decision applies to the complete true-conflict set and then saves automatically. Cancel retains original RAM/base. After a decision, a fresh authorized GET checks for changes during the choice; changed content/authority restarts comparison and, when needed, presents the refreshed whole conflict set. Revision/CAS protects the final dispatch race without automatic write retry.

Stable unique rule IDs with unchanged membership/order merge per rule; reordered or ambiguous rule arrays and ordered photo/supplier structures remain conservative conflict units. Mode/equipment stay coupled while legacy tool text remains independent. Late input rebases over the confirmed Save using its actual sent values as the baseline.

Explicit supported revival uses `save-local-revive-v1` with exact current draft, revision, generation, row/tombstone and necessary parent evidence. Existing create/view/edit permission, equipment availability, references, numbering, pending/read-only and atomicity checks remain. The old handler rejects the distinct action before partial mutation. A dispatched unsupported 422/receipt404 retains the original UNKNOWN barrier and never resends. Missing/ambiguous structures and delete-plus-payload changes refuse Mine; Theirs may preserve independent edits. No new schema, migration, data cleanup or historical rewrite occurs.

Compared Begin cancellation retires only its own provably unsent authority-read reservation. Returning may explicitly Save before the abandoned old read finishes; a late old callback cannot clear a newer journal or decrement its queue. Dispatched/UNKNOWN commands retain original operation IDs, scoped markers, generation and receipt-only recovery through departure. No automatic retry or 404-based unlock is added.

The actual caller/shared client/HTTP handlers are exercised with synthetic DOM, SQLite/R2 and clocks by `tests/iqc-save-choice.test.mjs`, `tests/iqc-compared-save-client.test.mjs`, `tests/iqc-revive-save.test.mjs`, `tests/iqc-save-choice-navigation.test.mjs`, `tests/iqc-revival-wire.test.mjs` and `tests/quality-master-explicit-refresh.test.mjs`. The handoff contains exact commit, commands, result counts and log hashes. Historical negative controls pin all changed FQC/IQC handler dependencies to the real predecessor; they never mix a new FQC adapter into an alleged exact old IQC handler.

Shared-client changes are explicitly identified in the FQC acceptance note. Final cache tags, CI and source-inverse pins remain coordinator integration work. Native desktop/iPhone, real accounts/data, remote CI and publication/deployment are unrun by this local module task.
