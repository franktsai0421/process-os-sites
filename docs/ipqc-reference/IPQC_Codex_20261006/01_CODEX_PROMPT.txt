【三、IPQC 選取規則】
1. 依當前線別、類別、工段及方塊已選產品，取得符合條件的真實 IPQC 項目。沿用既有有效／核准來源政策；來源未核准或讀取失敗要說明原因，不放寬成任意使用未核准標準。
2. AB 和 C 都採「錯誤代碼分組 → 展開 → 逐項勾選」。C 線早期只開啟查詢的方案已被本次項目勾選方案取代。舊查詢設定保留相容性，不臆造它原本未記錄的項目關聯。
3. 同代碼的不同項目可以分到不同方塊。同一製程類別、同工段、同版本範圍內，同一項目只能由一個方塊引用。
4. 同一項目適用多產品時只勾選一次，保留每產品適用關係與標準差異；不同項目即使名稱或代碼相同，也不能合併。
5. 先核對 AB／C 真實資料結構，使用穩定項目 ID 建立關聯，不以名稱、陣列索引或錯誤代碼代替項目 ID。
6. 三種狀態：未分配可勾；本方塊已選可取消；其他方塊已選不可重複勾，顯示占用方塊編號及名稱。
7. 可查閱標準、檢查方式敘述、全部檢查圖片、檢具及頻率。此頁只改分配，不直接改寫後台檢查標準。
8. 未分配完整只列入製程待補提醒，不新增阻擋製程送審的條件；不擴大修改品質模組既有送審政策。既有權限、待審鎖定及資料完整性保護仍沿用。
9. 產品適用條件變動、來源項目失效或關聯指向不存在項目時，保留原關聯並清楚提示，不偷偷刪除，也不假裝成正常未分配。
10. 後端保存也必須防止重複分配，不能只禁用 checkbox；多人同時選取同項目時，使用現有版本／同步機制防止同版本內兩方塊占用，並提供可理解的衝突訊息。

【四、反向引用：最新位置規格】
IPQC-AB／IPQC-C 的項目卡片、查看視窗、修改視窗，全部統一放在「檢查頻率」正下方，名稱為「製程引用」，唯讀、直接顯示，不增加第二層彈窗。
IPQC-C 原「檢查規則」顯示名稱改為「檢查頻率」，同步處理對應雙語標籤；僅改名稱，不改既有頻率設定與語意。卡片若沒有頻率，補頻率摘要，沒有設定就明示未設定，再接製程引用。

每筆至少顯示：線別 → 類別 → 工段 → 方塊編號／名稱 → 製程版本及狀態。
多個類別引用逐筆列出；共享草稿、待審與核准版分清楚，不把不同版本當作重複占用。
沒有引用、載入中、讀取失敗三種情況分開顯示。
引用由真正保存的製程項目關聯取得，不造展示資料，不以名称猜測。
取消草稿引用不得刪掉核准版引用；切換分頁或取消彈窗不產生引用。
先查清「套用流程內容 → 共享草稿同步 → 手動儲存快照 → 送審」現有邊界並在交付說明中寫清楚，引用只跟隨成功保存的關聯，不能另造一套保存行為或混淆未套用內容與保存狀態。
