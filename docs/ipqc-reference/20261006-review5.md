## 根因及修正

1. **AB 儲存／送審只操作當前群組**：按鈕以前只呼叫當前 scope。現在先取得有權限看見、存在且不待審的全部 AB 草稿，逐一呼叫既有 Save／Submit。送審前列出全部 scope，結果逐項呈現；未套用的修改先提示套用／取消，不能靜默漏存。不是跨模組混成一個案件，也不建立不存在的草稿。
2. **缺資料或內容沒變仍被阻擋**：共享核心只將明確 `missing` 分類與無實質修改改成固定案件的待補提醒。AB/C 缺標準也依最新使用者需求改為提醒；IQC／檢具把缺資料與非法已填值分開。其他 `error`、權限、CAS、固定案件、快照／來源完整性與待審鎖定保留。
3. **具有審核權限的員工仍無法自審**：移除共用核心與對應前端的 admin-only 判斷；同一送審者仍須明確勾選自審確認，案件留下 selfReview 記錄。角色／權限檢查優先，無權限帳號仍 403。FQC 的管理員歷史還原限制保留。
4. **C/INOX 套用不關閉，STAGE_INVALID**：INOX 同時存在 A 與 C，前端按群組建立工段時把 A-ASSY 空工段帶到 C workspace。修正建立範圍為當前線別；同步時只排除新產生、原快照不存在的跨線空占位。既存資料及有內容的異常工段不刪除，後端實際工段／產品驗證保留。失敗在彈窗內顯示原因並保留輸入。
5. **製程引用介面中越文混排**：狀態、標題、歷史入口跟隨介面語言；保留業務內容的原始文字及先前請求世代／身分失效防護。

這些政策修改位於日常共用程式，沒有限定只在 3020 生效；實際日常資料送審／核准仍由使用者操作。
