## 修改與根因

1. **送審政策**：共用 draft 核心先前僅有 process:platform advisory，品質 validator 的 missing 仍會阻擋。AB/C 現在明確選用 `ipqc-completeness-v1`，只有 `missing` 類別的 `IPQC_METHOD_MISSING`、`IPQC_FREQUENCY_MISSING`、`IPQC_PRODUCT_COVERAGE` 不阻擋。固定送審案件保存代碼、項目路徑與原因；legacy API 同步。標準、非法已填頻率、無效引用、必要檢具、角色、CAS、generation、待審鎖及無實質修改限制保留。
2. **AB 修改不能保存**：實際 3020 資料在 `A:BORUAXE1021` 三個項目保留不存在的產品 `1111111`（CUT-L1-01、CUT-L1-02、CUT-L3-01）。修改 CUT-L1-01 標準後 Apply 回 422；整份結構驗證撞到未修改的 CUT-L1-02 無效產品。原 UI 還會把候選清單外的舊產品默默漏掉。現在 working／Save 保留未變更的舊失效關聯供明確修復，新增無效關聯與送審／核准仍阻擋。彈窗列出失效勾選項，取消勾選才移除；失敗保留輸入並在彈窗顯示錯誤。legacy 格式錯誤也明確回 422。
3. **C 平台不能撤回**：reviewDraw 原本沒有撤回按鈕，操作區又依核准／發回權限顯示。現已獨立依 withdrawal 權限提供按鈕；API 接受具有版本確認平台查看權限及撤回權限的使用者，不要求 data／approve／reject。沿用理由、固定案件 ID 與後端保護；成功兩個入口同步，失敗顯示訊息。
4. **標準連到製程**：AB 擷取資料沒有 active 核准版，故候選來源不可用；不能把送審當作生效。依本輪使用者新授權，在 3020 真實副本正常保存／送審、由另一帳號核准，再核對 source scope、穩定 item ID、activeVersionId、產品、工段、啟用及製程引用。沒有直接修改 status 偽造核准。
