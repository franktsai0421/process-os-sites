# 製程平台現行需求

狀態：Current confirmed requirements。編輯台互動與 C 線入口以 2026-10-08 [PROCESS_EDITOR](PROCESS_EDITOR.md) 為準；本文件保留共享文稿、AB 分配及既有引用生命週期。

## 流程設定 IPQC（2026-10-08 更新）

目前 V3 編輯彈窗依類型分成 2／6／7 頁。一般作業的 AB IPQC 分配依已核准品質版本、現行產品路線、類別、工段與已選產品，按錯誤代碼分組後逐項勾選；C 編輯頁只有查詢開關，既有 C 分配唯讀保留，不因切換頁面刪除。舊 C 分配 API／反向引用保留相容。用穩定項目 ID 關聯，同類別／線別／工段及製程版本內只允許一個方塊占用同項目；同代碼不同項目可分開。多產品保留每個適用產品，不合併不同項目。

只改分配，不改後台標準。來源未核准、來源失效或產品條件改變要明示；失效原關聯保留並允許明確移除。未分配列待補，不新增送審阻擋。切分頁保留未套用內容；取消不保存。沿用 Apply → 共享工作內容同步 → 手動 Save → 固定 Submit → Review，後端包含 CAS 重試均驗證最終內容的唯一占用。

AB／C 卡片、查看與修改視窗均在「檢查頻率」正下方顯示唯讀「製程引用」：線別 → 類別 → 工段 → 方塊編號／名稱 → 版本／狀態。由成功保存的關聯產生，區分已同步未 Save、已 Save、待審、核准及歷史；載入中、無引用和讀取失敗分開。移除草稿引用不刪核准引用。

日常引用預設只查 working／pending／active；歷史須明確按需分頁，沿用私人內容與歷史權限。revision 未變更回傳輕量結果，不能在定時刷新時展開全部歷史。非同步來源／引用的成功及失敗回應都須核對目前實際登入身分與請求世代，避免切換帳號或重載後由舊回應覆蓋。

C 查看／修改單欄順序：基本資訊 → 啟用標準／CPK → 檢查標準 → 方式敘述 → 圖片 → 方式／檢具 → 檢查頻率 → 製程引用 → 備註 → 底部按鈕。保留照片多張、備註、位置、排序，檢具、頻率語意及 CPK。

僅隱藏畫布流程類型預設媒體、彈窗「流程資料照片／影片」及下拉「含預設照片」提示並收合空間；不刪媒體資料，不影響其他照片。舊 `operation.ipqc` 文字保留但不再提供輸入框，不自動轉為項目。畫布、BOM 選取及設備分頁現依 PROCESS_EDITOR 更新；本輪沒有重設發送與播放。

## 送審與安全邊界

單一共享草稿。資料、方塊、連線或 IPQC 分配未完成，列待補提醒，不因此阻擋製程平台送審。放寬不取消角色權限、待審鎖定或適用 BOM 互鎖；無實質修改改為提醒，跨模組內容待補與自審採 [共享草稿最新規則](SHARED_DRAFT.md)。損壞快照、技術錯誤及 revision/generation 衝突不是業務待補。

連線須遵守入口／出口方向及禁止循環；不完整連線不等於非法連線。產品、主資料、照片、歷史及 legacy 引用不得因待補被自動補造、代換或刪除。

## 核准與資料傳遞驗收

至少驗證共享草稿 → Save → 固定案件 → 核准 → 入口發送平台；按影響延伸產線播放與產品製程狀態。區分 working／saved／effective，確認下游使用核准版、權限、適用路線及待補提示。無法執行的路徑如實顯示，不代換成別的產品內容。

既有每線最多三個不重複產品、類別優先選取及產品相關工段的現況見[製程模組](../../../AI_CONTEXT/modules/PROCESS.md)。不從舊測試推定新增業務限制。

## 實作差距／待核對

- lib/process-authoring-workflow.ts 的 advisory 白名單包含 BOM 未分配；它與編輯時單一料件歸屬互鎖是不同關卡，不能宣稱全部 BOM 限制取消。
- V3 adapter 現由 process-editor-integrity 在最終 Apply 內容檢查入口／出口數量、循環、非法目標、BOM 來源與跨工段占用；舊違規保留列待確認。完整舊版非 V3 寫入入口並未因此宣稱重新驗收。
- 最新隔離結果及真實 AB 缺少核准來源的限制見 [驗收紀錄](../../ipqc-reference/20261006-acceptance.md)；不把隔離通過當成日常 Local 或正式發送驗收。
