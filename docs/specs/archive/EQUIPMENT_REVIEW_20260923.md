# 品質系統資料庫：草稿與主管審核流程

依 2026-09-23 提供的中控 AB／C、FQC 與版本確認平台畫面整理，作為後續實作的共同規則。此頁 `equipment-ui-hierarchy.html` 是可操作樣板；正式品質後台和 D1／R2 尚未接線。

## 共同操作規則

1. 預設顯示目前生效的已核准版本，例如 V1。歷史版可以從「選擇版本／草稿」切換並唯讀查看當時的資料和畫面。切換歷史版不會把舊資料套用到新草稿。
2. 建檔人員按「開始修改／刪除資料」才從目前生效版本建立下一版草稿。例如生效 V1 → V2 草稿，生效 V2 → V3 草稿；同一版草稿未結案時繼續編輯它，不另開平行草稿。
3. 編輯期間可以按「儲存草稿」，記錄儲存時間；選單可選草稿或歷史版。編輯、刪除及新增都只改草稿，不影響已生效版。
4. 按「送出主管審核」前檢查本次新增或修改設備／分類的必要欄位、照片和關聯；失敗項目列於「待確認清單」下方的「送審前檢查」，可跳到欄位修正。驗證通過才建送審案件，記錄送審時間並鎖定編輯。送審期間仍能查看案件或由建檔人員「解除送審，繼續修改」，撤回後案件退出待審清單，保留稽核紀錄。
5. 「版本確認平台 → 品質系統資料庫」顯示待審案件。主管點「確認版本」或「發回修改」都必須填意見；空白不可執行。
6. 發回後案件從主管待審清單移除，建檔人員回到**同一版草稿**繼續修改、儲存、重新送審；發回意見和時間保留於歷程。
7. 核准後記錄意見、核准人和時間，該草稿成為新的已核准生效版；原版保留唯讀歷史。再按「開始修改／刪除資料」才建立下一版草稿。

| 狀態 | 建檔人員 | 主管 | 生效資料 |
| --- | --- | --- | --- |
| 已核准／無草稿 | 開始修改，查看歷史版 | 查看已核准版 | 維持既有版 |
| 草稿 | 修改／刪除、儲存草稿、送審 | 可查看 | 維持既有版 |
| 主管審核中 | 查看案件、解除送審；不可編輯 | 填意見後確認版本或發回修改 | 維持既有版 |
| 發回修改 | 接續同一草稿、儲存、再送審 | 查歷史意見 | 維持既有版 |
| 已核准 | 查看核准時間、意見和歷史版；可建立下版草稿 | 查審核紀錄 | 新版生效 |

## FQC 與中控／檢具流程比對

你提供的 FQC 截圖有「目前查閱 V2／草稿」、「儲存草稿」、「送出主管審核」、「主管審核中」、「解除送審，繼續修改」、「查看送審案件」，並在版本確認平台的「品質系統資料庫」出現 FQC V2 待審。這些**畫面上的主流程與中控一致**。截圖中的 FQC 平台可見操作歷程和送審案件，**但不能由截圖證實**主管確認／發回時意見是否強制必填、發回後案件是否退出清單、跨裝置儲存或是否有可用的正式後端。實際程式尚未提供，因此 FQC 這些規則尚未完成程式核對或修改。

## FQC「新增檢查項目」待修正規格

- 「啟用」只控制**檢查項目本身**是否啟用，與檢查週期獨立：即使沒有選週期，勾選啟用也不得偷偷加入任何週期；取消啟用不得清除原來設定的週期。
- 週期是獨立多選（依實際產品規則保存）；加入「每半年檢查」。選項短文案為「每週檢查」、「每月檢查」、「每季檢查」、「每半年檢查」、「每年檢查」（若既有清單沒有某項，保留既有項並只補半年）。不要用「加入月檢查列表」這類長句放在選項框內。
- 資料模型分成 `item.enabled: boolean` 和 `item.inspection_cycles: string[]`；儲存、匯入、顯示、審核差異比較應分別讀寫，不能共用同一布林欄位。以啟用／停用 × 有／沒有週期的四種組合測試。
- 此項目前**尚未修改 FQC 正式介面**：本次交付的來源只有檢具頁面與 FQC 畫面截圖，缺少「新增檢查項目」原始檔或正式網站操作權限。

## 正式後端與跨裝置接線

正式導入需在 D1 儲存獨立的生效版本、單一開放草稿、草稿修訂號、送審案件、意見、時間與稽核歷程；照片放 R2，D1 記物件鍵。草稿保存及主管決策都要由後端核身、檢查角色與資料修訂號；審核狀態轉移要在交易中完成。檢具頁面目前只在同一瀏覽器 IndexedDB 演示流程，未實際連接品質後台，不保證換瀏覽器或換電腦仍有資料。資料表和 API 方向另見 `equipment-d1-r2-plan.md`。
