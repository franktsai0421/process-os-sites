# 給 Codex 的工作指令

請先讀倉庫 `AGENTS.md`、現有品質系統 FQC／IQC／IPQC-A/B、共用草稿／審核、i18n 與 migration 規範，再依本包 `README.md`、`IPQC-C_UI規格.md`、`IPQC-C_資料結構.md`、`IPQC-C_首次資料建置與驗收.md`、`UI/畫面索引與雙語欄位.md` 實作 IPQC-C。

1. **越文為網頁預設，中文可切換**；導覽、表單、驗證、審核訊息兩種語言共用同一資料鍵。產品名、越文錯誤名稱、檢查標準及來源方法／頻率保留越文原文，不自動翻譯。逐張對照兩個 UI 總覽的同序 19 畫面。
2. 產品與工段只讀現行 C 線主檔；產品搜尋支援越文輸入法組字，選工段、選錯誤代碼後看項目。兩層各有獨立的新增／修改／刪除，編號系統接續且唯讀、不重用。標準與 CPK 啟用分開。
3. 接共用品質草稿、衝突、送審鎖定、主管退回／生效、歷史及重新登入續編。圖片由網站管理；舊缺值保留，新項目送審時驗必要欄位。
4. **不要在 IPQC-C 頁面或入口實作 Excel 匯入、匯出、空白範本、上傳、下載或匯入差異預覽按鈕。** 首次建資料只使用 `資料/正式匯入/IPQC-C_越文首次建置來源_862筆.xlsx`，其欄名、文字與狀態均為越文，A–D 已逐列展開。原中越檔只供追溯。首次建置須重新比對線上生效主檔與已發號，不因缺列刪資料或覆蓋網站圖片。封存檔不得建入。
5. 實作並驗證兩語切換不改越文業務內容、兩層 CRUD、首批資料核對、合併儲存格、已發碼衝突、舊空值、重試不重複建列、共用草稿與審核。報告變動檔案、測試及與來源快照的差異。遵守當時倉庫的發布程序。

此交接包是規格和來源，尚未授權將來源資料直接寫入 Production。
