## 二 頁面配置

桌機左清單、右完整明細，可展開整份報告；手機單欄，選取與返回保留位置和輸入。長標準、樣品、結果、照片和歷史可展開；報錯與待補可定位具體項目／結果列。

| 區域 | 功能 |
| --- | --- |
| 四入口 | FQC／IQC／模具檢查／檢具與測試設備校準，各模組業務規則獨立 |
| 排程設定 | 先預覽起始日、首次期別及頻率交接，再确认啟用 |
| 應檢清單 | 勾尚未安排工作，批次放進同一計畫；已占用或完成不可重排 |
| 檢查計畫 | 草稿、待審、需建報告、已建報告、歷史、捨棄分框，核准後有對應報告入口 |
| 報告與申請 | 初測 RPT、複測 RTS、更正 COR、免做 WVR、處置 DSP 分類 |
| 異常追蹤 | 待改善、複測中、待確認結案、已結案、處置結案、本期免做 |
| 搜尋與歷史 | 查當次來源、產品／樣品、期別／實際日、編號、結果及所有歷次文件 |
| 文稿區 | 共用版本卡、手動Save、固定送審、撤回／發回／歷史；報錯紅、待補黃、操作紀錄藍 |

分類定位只移動左清單相應框，附數量、零項停用，保留右明細。草稿／已送審／完成審核快捷縮小文件檢視，仍不縮小 Save／Submit 範圍。統計卡及不合格快捷採範圍標記，其他列保留，再點取消；進階条件另外篩選，因此可見標記數可能少於全域統計。已選列用藍底和正在查看編號表明。重畫、篩選、上傳不應跳到頁頂。

## 三 檢查單位與資料關係

一筆 FQC 工作是「檢查項目＋期別」，不是每個涵蓋產品各一份，也不是 IQC 來料批次。例：本月尺寸檢查涵蓋甲乙丙，本次只測甲，報告同時標涵蓋甲乙丙／實測甲。搜乙可找到報告，但不能宣稱乙已實測合格。

| 資料 | 保存內容 |
| --- | --- |
| Source | 標準ID／版本／生效日、項目ID／名稱／編號、線別／類別／錯誤碼、說明、頻率、涵蓋產品code／name |
| Job | itemId＋起日＋截止日身分、期別、Source、目前planId、完成紀錄 |
| Document | 穩定ID／不可重用number、kind、建立者／時間、planId／caseId／correctionOf、文稿、取消與下游影響 |
| Line | jobId、當次Source、results；複測的固定requiredSamples |
| ResultRow | 獨立ID、samples、判定、value、notes、photos |
| Case | 原工作／計畫、初測及全部複測、待驗證原樣品、改善、狀態及事件 |
| SharedDraft | working、手動saved、固定pending案件、正式active、保存／審核歷史與並行保護 |

~~~mermaid
flowchart LR
 S[正式標準] --> J[項目與期別工作]
 J --> P[檢查計畫]
 P --> R[初測報告]
 R --> C[異常案件]
 C --> T[獨立複測報告]
 C --> W[免做或處置文件]
 T --> C
~~~

主檔改名、範圍、停用、改版不回寫既有 Source。填報不能任意改文件項目、來源身分或原樣品。D1 shared-state 與 R2 不可變內容／照片沿用，邏輯控制為 routineFqcControl，沒有新正規化SQL表。API 的 familyId／reportAvailability／dependencies／workingIssues／savedIssues 是讀取投影；raw封裝與API表示不同不直接等於業務資料變動。

## 四 排程與頻率

只納入正式生效、未刪除、啟用、可解析時間頻率的項目；不必再勾納入。非定期不自動排程，未知／自訂／待確認頻率先提醒，不猜日期。half_yearly 映射為半年。

| 頻率 | 公司曆期 |
| --- | --- |
| 每週 | 星期一至星期日 |
| 每月 | 月初1日至月底 |
| 每季 | 1–3、4–6、7–9、10–12月 |
| 每半年 | 1–6、7–12月 |
| 每年 | 1月1日至12月31日 |

首次從管理起始日與標準生效日較晚者所在當期開始，不追算此前期別；未来起日未到不生工作。已有文件後起始日鎖定；頻率在主檔修改並核准，既有工作不刪除重算。

頻率變更從最後截止日翌日接續，首段可較短，其後對齊新曆期。例如10月月期至10/31，轉週後11/1為交接段，下一週11/2–11/8；保持無空窗、無重疊、不改舊工作。

生成採開頁／同步／來源變更時按公司當日補齊；停機後下次補齊，不另外有全天候daemon。工作身分防重整／多人／重試重複，只讀者不觸發生成。逾期為 end早於公司當日且無completion，截止日當天不算，與異常未結案分開。

## 五 計畫到報告的流程

1. 勾尚未安排工作，建一份批次計畫；建立者記負責人，立即占用工作。
2. 編輯後手動Save，再Submit最後成功Save的整份快照。
3. 核准計畫後才建執行報告，可選仍可填報的部分項目。
4. 每項填樣品、判定、值、原因／照片；允許部分填寫先Save。
5. 任一結果列缺必填，整份Submit阻擋並定位缺漏。
6. 報告核准後留存，逐工作分流完成與異常。

計畫明示尚未／部分／已建立報告；已有同系譜草稿或待審就接續，不另建重複報告。建立報告需計畫目前核准、項目屬於計畫、工作仍屬同家族、沒有不允許的占用或重複初測。取消新版後舊正式版本不自動搶回工作。篩選不縮小整份文稿；多人同步後清除已被安排的勾選。

## 六 最新樣品與結果列條件

本節取代舊「同份報告同樣品跨列再測」。

| 情境 | 有效規則 |
| --- | --- |
| 初測已測結果 | 每結果列恰好一個涵蓋品項，同項各列不可重複 |
| 不同檢查項目 | 可各自檢查相同品項，不混成同項跨列重複 |
| 初測新增列 | 使用者明確按新增才建，選尚未用的品項，無可用樣品就停用 |
| 複測建立 | 固定原待驗證樣品，每個必要樣品一個空白結果列，不複製判定／值／原因／照片 |
| 複測選樣 | 直接顯示請用原樣品檢查及code／name，不可替換；無再測／建立原樣品按鈕 |
| 複測追加列 | 只接續尚未填報的固定原樣品，無可用者不新增重複空白列 |
| 無法測試 | samples空白、填原因；保留待驗證義務，不假造實測 |
| 數量及身分 | 每項最多100列，每列ID獨立 |
| 展開狀態 | 使用者決定，上傳／移除／重畫不新增或展開其他列 |
| 舊多選／重複草稿 | 不默默改樣品，樣品不變可存其他欄位；新Submit須符合新限制 |
| 舊正式報告 | 唯讀保留，舊失敗聚合仍可回查 |

同品項可在下一份獨立複測報告再次檢驗，禁止的是新報告同一項目跨列重複。現在samples記的是品項code，不是個別實體序號；若要同品項多個試件，需先定模型。

## 七 送審與核准必要條件

所有文件要非空名稱、有效日期、至少一項目；每個報告項目要結果列及判定。

| 結果 | 樣品 | 實測值 | 原因／說明 | 照片 |
| --- | --- | --- | --- | --- |
| 合格pass | 恰好一個 | 必填 | 選填 | 選填 |
| 不合格fail | 恰好一個 | 選填 | 必填 | 至少一張成功上傳 |
| 無法測試unable | 空白 | 選填 | 必填 | 選填 |
| 已測無法判定undetermined | 恰好一個 | 選填 | 必填 | 至少一張成功上傳 |

免做要原因；處置要原因、處置內容、成功上傳證據。複測另驗固定樣品／未測義務。**必填缺漏可Save不可Submit；非法結構、換來源、越界／重複／換樣或假的附件不是任意可存的缺漏。** 待補是畫面提示，後端仍阻擋送審，與部分主檔待補可送審的政策不同。

| 動作 | 條件 |
| --- | --- |
| Apply／同步 | 有edit，guard／revision／generation正確；不等於Save |
| Save | 有save，整份成功saved快照；失敗不顯示成功 |
| Submit | 有submit、savedId一致、必填通過、無pending；不代存最新輸入 |
| 無實質變更 | 已有active文稿的saved與active相同，FQC拒絕NO_SUBSTANTIVE_CHANGE；正式計畫受控復原的特定例外依現流程 |
| 待審 | 只鎖該份文件，不鎖全部FQC；不能編輯／Save取代固定案件 |
| Approve | 有approve、目前caseId／baseId正確，按固定案件生效 |
| Admin自審 | 明確確認並留actor／time／selfReview，換案清確認 |
| 非Admin自審 | FQC現行阻擋，不套其他主檔較寬政策 |
| Return | 有return，必填修改意見，發回後可編輯重送 |
| Withdraw | 有withdraw、目前固定案件；FQC額外操作理由可選填 |
| 額外操作理由 | FQC Submit／Withdraw不強迫，Approve可不填；業務原因、發回意見、結案原因仍各自必填 |

原頁與版本確認平台連同一案；後端確認審核結果，不以已按按鈕視為完成。

## 八 核准 本期完成與異常結案

報告核准是正式留存，可是不合格；本期完成是該項檢查／判定或核准終止；異常結案是改善驗證後確認或核准終止。三者獨立。

同項優先判fail，其次undetermined、unable、pass；有任一unable／undetermined，工作仍未完成。只有pass／fail的核准結果可完成本期檢查，不合格仍待改善，不能把全部涵蓋產品標合格。waiver／disposal核准按免做／處置終止本期。

~~~mermaid
flowchart TD
 A[初測核准] --> B{項目結果}
 B -->|合格| P[本期工作完成]
 B -->|不合格| C[待改善]
 C --> D[改善並建立獨立複測]
 D --> E[填報 Save Submit 核准]
 E -->|失敗或判定未完成| C
 E -->|必要樣品通過| F[待確認結案]
 F -->|有權限與結案原因| G[已結案]
 B -->|無法測試| U[核准補測計畫或免做]
 B -->|無法判定| D
 C -->|處置完整並核准| X[不合格 處置結案]
~~~

| 操作／狀態 | 條件 |
| --- | --- |
| open待改善 | 原失敗／判定未完成保留，走正式後續 |
| 改善並建立複測 | 有edit、非closed/disposed/waived、無同案未完成後續；fail需本次措施或失敗後已有改善 |
| 合併操作 | 同一次CAS写改善、事件、新文件；取消無寫入，失敗不留下半份 |
| retest複測中 | 已有後續報告／補測計畫，顯示編號與接續入口 |
| 再次失敗 | 正常Save／Submit／核准，繼續改善；不強迫改合格 |
| unable後續 | 先補測計畫核准，再報告；或符合條件的免做 |
| ready-close | 複測正式合格，仍不自動close |
| closed | 有approve、ready-close、revision一致、原因必填 |
| waived | 當前unable且無未解決原不合格，原因完整核准；不等於合格 |
| disposed | 當前fail或仍有原不合格，原因／處置／照片核准；保留fail |
| 終止案件 | 不建一般後續，更正走受控流程保留原事件 |

Case.requiredSamples是目前待驗證義務，通過後可清除；Line.requiredSamples是該份複測建立時固定快照。unable不造樣品也不消除原失敗。舊正式報告同樣品多列時，任一fail不被同份pass抵銷，後續獨立報告該樣品全部pass才解除，仍另確認結案。

新期正常產生工作，新期合格不自動關閉舊案；跨期補測保留原期別、實際日期與歷史。

## 九 編號 顏色與舊資料

| 文件 | 編號與識別 |
| --- | --- |
| 計畫 | FQC-PLN-日期-序號 |
| 初測 | FQC-RPT-日期-序號，藍色 |
| 複測 | FQC-RTS-日期-序號，紫色 |
| 一般報告更正 | FQC-COR-日期-序號，琥珀色 |
| 免做／處置 | FQC-WVR／FQC-DSP-日期-序號，獨立分類 |
| 案件 | FQC-CA-五位序號 |

日期是建立公司日，不是期別；序號按現有同kind文件數加一，捨棄仍保留。初測／複測／更正底層都是report，不是各前綴獨立每日流水。舊RPT不回寫，畫面／搜尋／匯出用RTS／COR別名並附原號，ID與連結保留。

待釐清：目前addDocument／reportType先caseId再correctionOf，所以相連異常的複測更正仍是RTS。最新需求概括說新更正用COR，此情境是否也改COR需定案。複測快捷尚有「複測／更正報告」舊文字，與獨立COR框的文字一致性也需收斂。

## 十 權限與並行保護

目前API權限模組為routine；角色模板、個人細格、啟用狀態和登入共同決定can，不能只靠角色名稱或按鈕隱藏。

| 能力 | 目前伺服器條件 |
| --- | --- |
| 清單／文件／歷史 | routine.view，granular history目前隨view |
| 修改 | view＋routine.edit |
| Save／Submit | view＋routine.save／routine.submit，另查文稿條件 |
| 建計畫／執行報告 | routine.create，另查edit及占用／計畫條件 |
| Withdraw | view＋routine.withdraw |
| Approve／結案 | view＋routine.approve，另查自審及案件 |
| Return | view＋routine.return，必填意見 |
| 排程預覽／設定 | view＋routine.settings |
| 捨棄／刪計畫 | routine.delete，另查edit／pending／相依；正式文件另查revoke |
| 反確認 | approve加approval.revoke及下游條件 |
| 更正 | edit加route的revise；can的approval.revise現在映射模組edit，普通UI不重開舊更正按鈕 |

舊view:data／approval.*表是相容來源，不能當今天全部動作表。照片PUT仍使用can('view:data')，新映射落在routine.view；UI只在可編輯草稿顯示上傳。API是否需直接查routine.edit是待討論一致性，尚未以只讀帳號實測；GET需登入及資料／審核查看權。

保留同源、登入、維護模式、細格權限、revision CAS、generation、欄位guard、工作占用、下游相依與每文件pending鎖。operationId＋actor＋命令指紋收據支援未知結果查證與原命令重試，不另造案件。寫入在備份與同一次shared-state CAS確認後成功，并行衝突重讀。來源／必要原樣品／正式快照不可普通patch改。FQC例行不受BOM待審阻擋，其他互鎖不改。

## 十一 照片與匯出

JPEG／PNG／WebP／GIF，每張最多25,000,000 bytes；驗MIME與簽名。PUT成功才入結果引用，寫文件再查R2 head，假photoId不算。SHA256身分與不可變key，同檔去重。每個結果列最多30張照片；普通文稿頂層文字欄位最多20,000字元，routine POST整個body上限2,000,000 bytes；這些是目前實作容量限制，不是任意長報告都已容量驗收。

移除草稿結果／處置證據只解未存引用，不刪R2、不改歷史、不自動Save；必要照片移除後補件才Submit。上傳開始固定目標photos陣列，等待期間移動／移除列不誤寫別列。

正式匯出從active.content產生獨立HTML，內嵌授權圖片bytes，含版本、結果、原樣品與審核紀錄／原號。需正式文件與歷史權；圖片讀取失敗不冒成功匯出。不是用截圖取代正式文件。

## 十二 反確認 更正 捨棄與復原

| 動作 | 條件 |
| --- | --- |
| 反確認計畫 | 已核准、無任何報告下游、有revoke、原因必填；換generation、清saved、重新送審 |
| 正式報告修訂 | 新correctionOf文件，保留原active／照片／案件與相依，不原地改正式 |
| 已結案報告更正 | 保留原結案事件，重新確認適用結果與結案／影響，不靜默移除異常 |
| 捨棄草稿 | 非pending，保存cancelled／flow／照片／案件／事件，僅釋放仍屬自己的占用 |
| 收回複測草稿 | 確認後沿可復原捨棄，回原案待處理，原失敗與正式報告不刪 |
| 待審收回 | 先Withdraw，不能直接當未送審草稿捨棄 |
| 正式計畫刪除 | 需revoke、無報告／案件／更正版相依；可復原取消，不物理刪 |
| 復原 | 再查占用／家族／案件／版本，不能搶已改派工作；正式計畫按受控流程再送審 |
| 下游影響 | 有權者確認並留原因／人／時間，不能自動解除所有異常 |

不得用舊終止文件覆蓋已前進案件。缺連結、不一致或相依衝突回明確error，保留輸入與歷史。

## 十三 搜尋與統計

線別→類別→項目聯動，上層變更清不相容下層。可跨線找同名項目，显示類別／錯誤碼／編號。分類來源包含正式後台與歷史，不只取已排程工作。搜尋產品／錯誤碼／項目／名稱／新舊編號／期別／實際日／結果／審核／案件；涵蓋快照與實測分列。

| 統計 | 判断 |
| --- | --- |
| 尚待完成 | job無completion |
| 待審核 | 未取消文件有pendingId |
| 異常未結案 | case非closed／disposed／waived |
| 逾期 | end早於當日且無completion |

結案／捨棄可歷史回查，不只取最後合格遮住原失敗。部分完成不能把整份計畫標完成。

## 十六 建議與ChatGPT決定的方向

以下只供討論，不因列出即授權實作。

| 優先 | 要決定的事 | 影響 |
| --- | --- | --- |
| 1 | FQC骨架是否定版 | 保留工作／計畫／報告／案件與最新14項，避免重做整個UI |
