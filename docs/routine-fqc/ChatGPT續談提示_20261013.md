# 給 ChatGPT 的 FQC 製作方向續談提示

我要討論「品質管理 → 例行檢查 → FQC」的製作方向。請完整閱讀附件guide.md或guide.txt；這是2026-10-13現有3040的設計、條件及驗收快照。先討論FQC，不直接開發IQC、模具檢查或校準。

請區分：已確認需求、現行程式、已有驗收證據、尚待我決定。10/12單選與固定原樣品優先於10/8跨列重測，舊權限表不能取代routine細格。API通過／唯讀手機模擬不等於全部原生與實機通過。

保留已定配置：項目加期別工作，涵蓋產品與實測分開；每文件一共享文稿，Apply不是Save，Submit取最後成功手動Save整份快照；初測每列一品項、同項跨列不重複，下一份複測固定原待驗證樣品；無再測／建立原樣品按鈕；上傳／移除不增列或展開其他列；移除只改未存引用、不刪歷史、必要照片缺漏擋Submit。

初測RPT藍、複測RTS紫、更正COR琥珀，原號ID連結保留。合格要樣品／值；fail或undetermined要樣品／原因／照片；unable要原因且不造樣品。缺漏可Save不可Submit。核准報告、本期完成、異常結案分開；改善與建複測一次完成，合格複測後另確認結案，免做／處置不變合格。伺服器細格權限、固定案件、CAS、generation、收據、占用和相依保留。

請先用一頁說明目前流程及是否適合實際工作，再列「維持／要改／待確認」三欄，不重新設計14項已定操作。優先討論品項code與實體試件／批次、實測值結構化、複測更正是否統一COR及分類文字、照片PUT與routine.edit一致性、Admin自審／缺漏阻擋／無實質變更的FQC特例。

每個擬改項目說明情境、文件／歷史／權限影響、資料相容和驗收方法。文字或分類修正不用整個資料模型重寫。最後給分階段FQC改善建議、少量真正需要我決定的問題及確認後可交Codex的差異規格。

專用初測0044、案件00020、複測0045已驗真照片、原生Save／Submit、固定樣品及API核准／結案。仍有Space未確認、390px編輯態完整鍵盤／觸控未驗、實體手機不可用、13項既有lint診斷、3000整合及發布未驗。保留證據界線，不改寫為PASS。
