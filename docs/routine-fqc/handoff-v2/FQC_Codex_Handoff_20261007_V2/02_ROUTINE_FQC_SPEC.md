## 2. 檢查單位、樣品與涵蓋產品
沿用線別→產品類別→錯誤代碼→檢查項目→包含產品。以檢查項目＋期別排程，不能自動拆成每產品一份應檢工作。
例如耐壓項目涵蓋甲乙丙，本月一筆應檢工作；本次實測甲。報告分別保存：來源標準ID/版本、項目ID/名稱/編號、線別/類別/錯誤代碼、涵蓋產品快照、本次實測樣品、結果、時間及照片。
實測樣品由可搜尋選單從該項目涵蓋产品中複選；顯示編號與名稱。同次不同樣品結果不同時，在同份報告分別記錄樣品與結果。無法測試不得虛填實測樣品。
核准完成該項本期檢查安排，不宣稱未測產品已實測合格。搜尋甲、乙、丙皆可找到報告，明確標「涵蓋甲乙丙／實測甲」。後台範圍改動不改寫舊報告。

## 3. 排程設定
FQC頁右上角「排程設定」，Admin／具設定權限者操作。未設定時顯示尚未開始管理及設定按鈕，不產生正式工作。
選管理起始日→預覽首次應檢項目、期別、截止日→確認啟用。從所在當期管理，不追算更早期別；未來起始日不得提前產生逾期。已有計畫或報告後不可直接改起始日重算。
正式生效、啟用、有時間頻率的FQC項目自動納入，不再勾一次納入定期。新項目從正式生效當期起算，不追溯。
頻率仍在原FQC標準頁修改，核准後適用；從下一個尚未產生期別生效，既有工作不刪除重算。預覽新頻率第一次適用期間及期限，避免空窗／重複。未能解析的自訂／舊頻率列待確認，不猜日期。
使用公司時區Asia/Ho_Chi_Minh；曆週／月／季／半年／年之界線、截止日及交接演算法需在實作文件明確列出，沿用有效規則；規格未定的邊界需明示，不靜默改成滾動天數。
重啟、重整、重試與多人操作不得重複產生同一應檢工作。其他功能未來可獨立設定起始日，本次只建置FQC。

## 4. 功能頁及UI
應檢清單／批次安排、計畫與報告、異常追蹤、搜尋與歷史、排程設定。
桌機左側清單右側完整明細；填報寬表，不逐項強迫彈窗。長標準、照片、歷史展開，長報告可佔全內容區。手機單欄清單／明細、結果卡片；保留返回位置、篩選及輸入。
沿用品質系統色系，輸入越文為主，標題及固定選項中越雙語。文稿／操作／報錯／待補／操作紀錄實際重用當前共同元件、順序、樣式，不由參考圖重設。
每筆待辦突出下一步及原因，清楚顯示已同步／未儲存／最後成功儲存。待辦與歷史分開，結案不消失。3040持續顯示測試環境。

## 5. 計畫與共享草稿
選項目→批次建立計畫→手動Save→Submit→核准→建立報告→逐項填報→Save→Submit→核准→分流。
建立帳號為負責人；計畫核准後才可建立執行報告。支援部分填報、漏項補排、跨期補交，避免重複占用同一應檢工作。
每份計畫、每份報告各一共享草稿；整份原子Save，不因搜尋／分頁縮小。Submit僅使用最後成功手動Save的固定快照，不代存後續輸入。鎖定該份案件，不鎖全FQC。
保留CAS、多人同步、固定案件、伺服器權限、待審鎖與完整歷史。發回／撤回後可編輯及重送。未知寫入結果不能當成功；重試不得重複案件。
接入既有版本確認平台，原頁與版本台連到同一案，避免審核副本。Admin自送自審須明確確認及紀錄；具模組存取權員工依動作權限編輯/Save/Submit/Withdraw，不新增一般員工核准權。
例行計畫、報告、異常處理不受BOM待審阻擋；其他模組互鎖不變。

## 6. 結果、必要內容與送審
同份報告允許混合結果，逐項或樣品結果列填寫，整份送審、核准後逐項分流。
|結果|送審內容|核准後|
|---|---|---|
|合格|實際結果與樣品紀錄，照片選填|本期該項完成|
|不合格|問題說明＋至少一張成功上傳照片|建立異常改善待辦|
|無法測試|原因必填，照片選填|待核准補測或免做，不直接完成|
|已測但無法判定|說明及照片必填|補充判定或複測，不直接完成|
不合格缺說明／照片可存草稿、不可送審；任一結果列不符合即阻擋整份Submit，標出位置與補件動作，初測與每次複測均適用。上傳失敗不可充當成功附件；保留輸入可重試。
這是本流程特定規則，不放寬或收緊其他主資料政策。舊提案「不合格缺照片先送審再補」停用。

## 7. 閉環與完成狀態
報告核准＝正式留存，結果可以是不合格或無法測試；計畫完成＝所有應檢項目已依規定完成檢查／判定或核准免做；異常結案＝改善驗證後有權限者確認，或核准處置結案。三者獨立，可顯示「計畫完成／異常未結案」。部分完成不可整份計畫完成。
合格：報告核准→本期完成。
不合格：異常→改善紀錄→複測→合格報告核准→主管/具權限者確認結案。
複測仍不合格：能正常Save/Submit/核准留存，繼續改善及下次複測，不能要求改選合格。每次獨立報告編號，串回原異常，照片與歷史不覆蓋。
處置結案：持續不合格但停止追蹤，可申請，必填原因、處置、證據，主管/Admin核准。保留「不合格・處置結案」，不改為合格。
無法測試：原因留存→核准補測安排→補測，依實際結果完成或轉異常；或核准本期免做→本期結束，下一期仍產生。免做不算合格。
已測無法判定：補充判定／複測，核准結果後依結果完成或轉異常。
不得用強迫合格、刪除案件、直接改status製造閉環。

## 8. 跨期、反確認及更正
舊異常未結案，下一期照常產生並提醒舊案；舊案由自己的新增改善／建立複測／申請處置結案操作繼續。下一期合格不自動關上期。跨期補測保留原期別、實際檢查日期與逾期紀錄。
已核准計畫尚未建立任何報告，才可填原因反確認；已有報告的計畫及正式報告走修訂／更正，保留原版與新舊連結。影響下游時列影響並追蹤，不靜默移除異常。
標準改版、改名、停用不改既有計畫／報告快照，提供差異提醒。草稿錯誤、載入失敗、權限不足、待補分開，API失敗不得當空資料寫回。

## 9. 搜尋與歷史
入口：FQC計畫與報告／異常追蹤；後台例行報告資料庫→FQC；原FQC錯誤代碼或項目回查。
條件：線別→類別→檢查項目；錯誤代碼、產品、報告/計畫編號；應檢期別與實際檢查日期；結果、審核狀態、異常狀態。
可直接跨線找項目，同名顯示類別、錯誤代碼、編號。快捷：不合格／未結案／已結案的不合格。產品搜尋匹配當時涵蓋產品，結果清楚標實測樣品；歷史不可只看最後一次合格。
明細含當次標準、說明、照片、改善、所有複測、操作者/時間、核准與結案紀錄。各入口共用持久資料及權限。正式報告匯出與畫面版本一致。
