# UI 參考與實作要求
V2含使用者原桌機概念參考及新生成的精緻視覺圖；均不是正式網站截圖。資料、日期、帳號、編號為示例，正式配色沿用現有品質系統。
開啟UI/index.html可切換六個桌機版面與手機閱讀版。此HTML只供瀏覽，不模擬完整工作流、不提供儲存、不連API；畫面上的業務按鈕均為示意。

|畫面|桌機佈局|手機|
|---|---|---|
|01 應檢與排程|四功能入口、工作統計；左應檢清單、右已選項目／啟用預覽|入口換行，清單和詳情單欄|
|02 計畫簽核|左待審計畫；右固定送審快照、項目與審核操作|先清單後明細，返回保留位置|
|03 填報|項目清單與實測樣品、四結果選項；依結果展開說明照片|每項一卡片，選結果後就地展開|
|04 報告審核|左待審；右混合結果、必備附件、核准後分流摘要|項目卡片，分流清楚|
|05 異常追蹤|左未結案／已結案；右多次失敗、改善、複測、結案時間線|歷史單欄，下一步清楚|
|06 搜尋歷史|篩選列、左報告清單、右完整歷史與照片|篩選可收折，清單選擇後明細單欄|

文稿／操作／報錯／待補／操作紀錄區在圖中只標「既有共用元件保留區」。其位置、尺寸、順序以本機當前實作為準，不能照這個占位區重做元件。
正式UI需完整空白、載入、查無結果、API失敗重試、待審唯讀、權限不足、CAS衝突與上傳失敗狀態，保存輸入/焦點/捲動。照片縮圖可開相簿，報告標準快照可展開。
產品樣品選單顯示代碼＋名稱、可輸入搜尋、多選；涵蓋範圍與實測樣品必須分開顯示。結果不同需拆結果列，不把所有樣品強制共用一個合格結果。
搜尋日期區分應檢期別/實際檢查日期；查涵蓋乙也能找實測甲的報告，需顯示匹配範圍與實測對象。
實作桌機至少1366及1920寬、手機390寬檢查文字、照片、長名稱、滾動、鍵盤焦點和底部按鈕。模擬不等於實體手機通過。

## V2 精緻桌機設計要求
- 主視覺：visual/FQC_DESKTOP_VISUAL_V2.png。原圖：visual/FQC_DESKTOP_USER_REFERENCE.png（相對UI目錄）。
- 適當提高資訊密度：表格清楚欄頭、交錯底色或分隔線、選取藍底、統一數字／日期對齊。保持1366普通桌機可讀，不照六宮格把正式頁面縮小。
- 待辦統計用少量數字卡呈現應檢／已安排／未安排，與實際查詢一致，點擊可套篩選；不要裝飾性圖表。
- 狀態用文字＋色標，不能只靠紅綠辨識。主要下一步突出，其餘按鈕降低視覺權重；不可執行時有原因。
- 詳情以標準／實測樣品／結果／照片／歷史分區；異常用時間線保留每次失敗，不只顯示最後合格。
- 搜尋結果與明細並排，長內容有明確捲動區；手機單欄不硬縮表格。

## 圖片中的細节以規格校正
1. 圖中將涵蓋／實測產品放在報告上方只是視覺簡化。正式資料與操作須在每個檢查項目下選樣品；一份報告有不同項目／範圍時不能共用錯誤選單。
2. 生成圖小字可能有錯字，不能OCR後直接當欄名。四入口正式名稱是FQC、IQC、模具檢查、檢具與測試設備校準；四結果為合格、不合格、無法測試、已測但無法判定。
3. 合格複測核准後仍須有權限者確認結案，不能照圖中的示例時間線推定自動結案。處置結案保留不合格。
4. 樣品複選不代表自動測完全部涵蓋產品。範圍甲乙丙、實測甲，搜尋乙仍找到，清楚呈現兩種身分。
5. 欄位沒畫到不代表刪除：仍保留線別／類別／項目篩選、兩種日期、照片必填、無法判定與免做等完整分支。
6. 不合格說明＋成功上傳照片是Submit條件；圖片中有縮圖不代表API上傳已完成。測試用test-evidence PNG驗證實際媒體流程。
7. 日期／數字／使用者及結果純示例，不匯入3000。文稿區不可照圖的簡化或省略而重新安排。
