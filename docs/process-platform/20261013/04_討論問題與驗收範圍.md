# 待討論設計與後續驗收

本節全部是待確認的設計問題，不新增目前規格。

## 先決定產品製程平台代表什麼

產品製程狀態維持「核准作業內容/準備狀態」，或擴充為「实际生產進度」？後者涉及工單、數量、開始/完成/異常、產品批次、責任人/工段、稽核與報表，現在的dispatchBoard不足以承擔。

## 四頁的具體選項

1. 產品狀態：路線＋逐工段內容、待補、目前核准版本与各主資料版本如何一起呈現？共用步驟/產品補充/設備/BOM/IPQC/媒體的層次、搜尋與手機操作。
2. 發送：維持每線三產品或調整？選擇顺序、撤销/清空/換產品、發送理由/操作者/時間、冲突提示；是否需要批次/數量/工單。哪些不可執行項必須阻擋、哪些核准advisory只提示？明確區分送審/核准/發送三道政策。
3. 版本策略：發送後一直跟隨最新effective，還是固定當次版本？主資料/IPQC更新如何保持相容與歷史？變更時是否提示使用者确认，设备如何得知。
4. 產線播放：單/多產品切換、工段固定、方塊順序/圖形、媒體、全螢幕、触控與电视可读性；無適用工段/尚未核准/缺引用/断网的顯示。
5. 入口工段播放：访客設備與平台登入的存取差異；能否切線/工段、如何返回/退出、是否固定设备；公开读取范围與照片权限必须明确。
6. 即時更新：目前页面更新能力先核对；若新增輪詢/推送，需保持revision与身分隔離、未變更不重繪、滚动/媒体播放不被重置、断网/陈旧版本显式提示。

## 後續必須驗收的流程

隔離资料从製程編輯Apply → 畫布同步 → 手動Save → Submit → 版本平台固定案件 → 核准 → 入口發送 → 產品狀態 → 產線播放 → 入口工段播放，核对稳定ID、effective版本、產品適用路線及BOM/IPQC/媒體。

並行编辑/過期revision、pending锁、员工/審核者/ADMIN/device访问、自審確認、無修改與待補送審、發回/撤回/再送、断网未知收据、切帐號、重开持久性。发送的零/一/三/重複/錯線/缺版本/缺工段案例，客户端和后端必须一致。

桌機與iPhone尺寸的中越文可讀、觸控、焦点、彈窗、滚动與全螢幕；实體裝置與电视播放另行驗收。
