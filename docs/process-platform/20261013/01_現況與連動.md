# 現況與連動

以下是目前程式行為與欄位的整理，不是新改版的需求定案。

| 入口 | 現況與主要來源 | 與其他頁面連動 |
| --- | --- | --- |
| 製程編輯台 editor | 類別＋線別 workspace，各工段流程方塊、產品、連線、BOM、設備、共用/產品專用作業及IPQC | 取核准主資料；Apply同步working，Save固定快照，Submit建立固定案件 |
| 資料後台 data | AB/C產品與類別、預設/例外路線、線別工段、BOM、流程模板與設備、帳號/角色/權限，以及品質標準 | 主資料核准投影才成為下游來源；品質IPQC是已核准標準，製程只分配/查詢 |
| 版本確認平台 approval | 主資料與製程案件分開；查看固定內容、比對、核准/發回/撤回、歷史 | V3製程整個平台一个scope；核准产生effective，其他模块各自独立 |
| 產品製程狀態 productStatus | 依線別、類別與產品檢視核准路線及各工段適用流程、BOM、設備、作業、IPQC、媒體 | 不讀目前未核准working；目前不是生產工單完成進度或實際產量系統 |
| 發送介面 dispatch | 各線最多三個不重複產品，先選類別再選產品，按發送更新dispatchBoard；下方監控與播放內容同源 | 讀核准製程與有效產品路線；檢查後送generic shared-state/CAS保存；仍需後續實際發送閉環驗證 |
| 產線播放台 player | 選線別/工段，顯示目前發送產品及該工段適用的核准方塊；支援全螢幕 | 工段選單由已發送產品有效路線聯集篩選；不適用產品明示，不代換其他產品 |
| 入口「進入工段播放」 | 登入頁選線別/工段，進入同一player，建立device前端身分 | 是另一條入口；前端device≠平台帳號或伺服器授權，需單獨驗證匿名投影/讀取/媒體與全螢幕退出 |

## 共同資料流

資料後台/品質標準核准 → 有效產品、路線、BOM、流程模板、設備、IPQC → 製程共享working → Apply/同步 → 手動Save的固定saved → Submit固定案件/pending鎖 → Review/核准 → effective製程 → 產品狀態/發送 → dispatchBoard各線产品码 → 產線/入口工段播放。

發回與撤回保留案件、理由、人員、時間與歷史；不能把目前篩選的一個類別或一條線當成整份送審內容。

## 頁面來源不是單一app.js

app.js提供基礎畫面；version-workflow.js包裝render/bindView，使用核准版本產生productStatusPage/playerPage/dispatchPage。process-authoring-v3.js在已採用V3的範圍提供整平台effective投影與待補提示。dual-system.js包裝入口/导航，permission-controls及user-access.js處理權限與伺服器登入。bootstrap.js按index.html所列順序載入。新設計不能只修改早期同名函式而忽略後載入包裝。

目前dispatchBoard只是線別→產品碼陣列，未保存每次發送的工單、數量、當時固定製程版本ID、派工人/時間、設備播放確認或生產進度。若要新增，先討論其業務語意、相容性與資料流，不能把現有產品製程狀態當成這些功能已存在。

產品專用內容以productInstructionSteps、productMediaItems等欄位補充；播放只看所選/已發送產品自己的補充。歷史free text與舊IPQC引用保留，不能因畫面改版清掉。
