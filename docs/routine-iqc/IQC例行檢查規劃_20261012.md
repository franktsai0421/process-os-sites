# IQC例行檢查規劃 可沿用設計 批次抽樣差異與審核條件

日期：2026年10月12日。狀態：Proposal，等待使用者確認差異；不是已定案規格或已實作功能。

**沿用FQC的工作清單、計畫、報告、固定審核、異常與歷史；IQC增加進料批次和抽樣判定，不重做整套介面。** IQC時間檢查與批次檢查保留兩種工作來源；單件測試、批次接受、文件核准及異常結案分別表示。以下「沿用」引用既有共用基線；「建議」與C01至C10均待確認，不授權修改程式、主檔或業務資料。

FQC後續修正提示：2026-10-12新批註已將FQC改為單列單樣品、同項跨列不重複、移除再測按鈕，詳見[最新需求](../specs/current/ROUTINE_FQC.md#2026年10月12日單樣品與複測回饋)。本IQC提案的實體樣品計數／複驗差異仍待C10確認，不視為隨FQC自動定案。

## 現況與規劃邊界

FQC續談包為2026年10月8日保存版，21個列冊檔案雜湊核對通過。指南與IQC原主檔規格目前仍與包內相同。現在checkout的HEAD已向前推進，後續實作要讀最新工作區，不能用包內程式覆蓋。

IQC主檔已有零件、類別、排序供應商、錯誤代碼、檢查項目、目視／設備方式、照片及多條規則。規則分來源原文、批次、時間；批次種類為AQL、固定件數、批次數量、自訂，時間為週、月、季、半年、年、自訂。來源原文及無法可靠解析值必須保留，不猜AQL或供應商。

目前確認的例行執行參考仍是FQC，IQC例行入口尚未完成。IQC主檔審核是整個IQC標準庫的文稿；建議IQC執行計畫／報告各自一份文稿，與主檔、FQC及其他批次獨立，不把它們合成共享案件。

## 可沿用與需要改動的設計

| 配置 | 可沿用FQC | IQC差異或待確認 |
| --- | --- | --- |
| 導航 | 應檢清單、檢查計畫、報告與申請、異常追蹤、搜尋與歷史 | 應檢清單增加「進料批次／時間檢查」切換，不另建一套重複頁面 |
| 清單閱讀 | 桌機左清單右明細，手機單欄；內部捲軸、焦點、輸入保留 | 列標題以零件＋實際供應商＋進料批／期別，避免相同零件混批 |
| 分類定位 | 上方有數量的分類按鈕、分框、選中藍色及正在查看編號 | 初驗、複驗、免驗／免做、批次處置分開；名稱由差異表確認 |
| 階段與下一步 | 未安排、草稿、已送審、計畫核准待建報告、正式留存 | 另顯示待判定、批次可接受／不接受、待放行決策，不能只寫正式核准 |
| 統計 | 工作未完成、待審、異常未結案、逾期分開；範圍標記不改結果 | 增加待檢批次、檢查不足批次；逾期按批次承諾日期，不套月末 |
| 表單與提示 | 紅色報錯、黃色待補、藍色紀錄，前往修改，緊湊版本卡 | 抽樣應檢數、已檢獨立件數、缺件數及判定依據必須就近可見 |
| 文稿與審核 | 同步／Apply、手動Save、固定Submit、正式版與歷史分開 | 沿用固定快照機制；理由、自審、執行缺漏及放行權限另決定 |
| 異常後續 | 改善與建複測合併、原文件連結、可追溯歷次結果 | 保留原批／原樣品；補抽、換樣、退貨與再交貨不可當同樣品複測 |
| 防重複與復原 | 權限、revision／CAS、固定案件、收據、相依鎖與軟取消 | 同零件不同進料批是不同工作；同一批重試不可重複建工作 |
| 語言與設備 | 中越固定標籤；越文原值保留，設備穩定ID與來源快照 | 新增批次及抽樣詞彙，不推測新設備可用／校準政策 |

## 建議頁面與工作單位

IQC頂部保留原五個功能分頁。應檢清單先分進料批次與時間檢查，再按未安排、待確認規則、計畫草稿、待審、需建報告、檢驗中、已完成分框。異常清單另分待處理、複驗中、待結案、已結案、退貨／其他處置結案，不把各種文件全部混在一張LIST。

批次明細頂端固定顯示：進料紀錄、供應商批號、內部檢驗批號、零件編號／名稱、實際供應商、批量與單位、到貨日期、檢查截止日。採購單、收貨單、證明文件可另列；第一版必填範圍見C01。主檔零件的供應商清單只是允許引用的來源，不代表本次實際來自所有供應商。

**建議同一進料批可包含多項檢查，但不同供應商、零件或無法證明同質的批次分開判定。** 第一版一份執行報告綁一個檢驗批，避免同報告含不同批卻只顯示一個結論；是否允許跨批共同計畫見C02。

| 工作來源 | 建議識別 | 產生時機 |
| --- | --- | --- |
| 時間檢查 | 零件穩定ID＋項目／規則ID＋期別 | 正式啟用的可解析時間規則，沿用公司UTC加7曆期 |
| 批次檢查 | 進料事件／內部批ID＋零件ID＋實際供應商ID＋項目／規則ID | 已確認進料資料及批次規則，正常建立或未來收貨銜接 |
| 同批分次到貨 | 必須指定同一批追加，或拆成新檢驗批 | 原報告已固定後，不靜默增加批量或改抽樣數 |
| 退貨後再次來料 | 新進料事件與原批關聯 | 不覆蓋原拒收／退貨報告 |
| 同項多條規則 | 保留各ruleId與適用條件 | 由C02決定時間／批次並存及多批次規則是並行、擇一還是不同情境 |

這些是概念關係，沒有新增任何實際欄位、資料表或migration。來源版本在建立計畫／報告時固定；批次身分、批量或抽樣方案後續變更須受控改版及重審，不能改掉已核准證據。

## 批次抽樣與FQC的關鍵差異

| 議題 | FQC保存基線 | IQC批次規劃 |
| --- | --- | --- |
| 抽樣對象 | 涵蓋產品編號，記實測產品 | 同一零件一批中有多個實體樣品，需獨立樣品ID，不以零件碼充當多件樣品 |
| 觸發 | 項目＋曆期 | 進料批次事件；不能月期冒充每批檢查 |
| 數量 | 記結果列與所測產品 | 批量N、應抽n、已完成獨立樣品數、缺件、必要缺陷統計 |
| 判定 | 各結果列合格／不合格等 | 單件結果＋項目抽樣判定＋整批決策；各層分開 |
| 同樣品重測 | 可跨列重測，原正式資料不改 | 重測保留測次，但同件只計一個抽樣單位；不靠多測湊樣本數 |
| 不合格聚合 | 同報告一個樣品有失敗即保留失敗 | 單件失敗仍保留；整批是否不接受須依已確認抽樣方案，不直接套FQC「任一失敗整批失敗」 |
| 完成 | 正式留存且無未測／未判定可完成該期，異常另追 | 檢驗完成、報告核准、整批接受、庫存放行、異常結案分開；具體完成條件見C08 |
| 無法測試／免做 | 原期義務保留，可核准本期免做 | 未測不能冒充接受；批次免驗需單獨政策，不能用本期免做關閉整批風險 |

### 各抽樣類型的待決參數

| 現有主檔類型 | 可引用的內容 | 執行前還需明確 |
| --- | --- | --- |
| AQL | 現有AQL值及ruleId | 採用的正式抽樣規範及版本／公司表；檢驗水準、正常／加嚴／減量、一次／二次等方案、批量區間與單位、樣本數及接收／拒收界線，必要時按缺陷等級分開 |
| 固定件數 | 固定件數值 | 需為有效整數；少於要求的批是否全檢；接受界線、未完成及破壞試驗處理 |
| 批次數量 | 現有數值與原文 | 數值是應檢件數、每若干件觸發一次、批量區間或其他意思；未確認前不解讀成全檢或百分比 |
| 自訂 | 越文名稱、文字／數值 | 可供人執行的抽樣與接受說明；是否人工確認；未明確不能計算 |
| 時間 | 週到年及自訂文字 | 與批次並存時是否另外檢查；自訂週期未明確先列待確認，不猜日期 |

AQL不是「抽批量乘AQL百分比」的取樣公式。一次抽樣至少要確定樣本數與接受界線；採查表方案時還需批量、檢驗水準及方案種類等輸入。這裡不選用任何預設標準、表格、AQL值或歷史規範版本。[NIST單次抽樣原理](https://www.itl.nist.gov/div898/handbook/pmc/section2/pmc23.htm)、[查表所需資訊](https://www.itl.nist.gov/div898/handbook/pmc/section2/pmc231.htm)。

建議第一版先支援使用者確認的單次計數抽樣，確認「不合格品件數」或「缺陷數」的計數單位。若每件可有多個缺陷，不可把缺陷筆數直接當不合格件數。沒有正式依據不啟用自動計算，也不宣稱符合某一標準。

舉例僅說明畫面：若使用者確認某方案為抽5件、接受不合格件數最多1件，5件中1件不合格時，單件仍標不合格，而批次可依該方案接受；不是自動改寫該件合格。這不是建議的實際抽樣數值。實際是否仍建立異常、是否需供應商改善由C05決定。

### 樣品與複驗

建議樣品ID在批次內獨立，例如批A的S001與批B的S001是不同樣品；同件跨項目可共用實體身分，但各項目結果和完成件數獨立。採樣箱位、位置、時間及操作者可記錄，隨機／分層或其他取樣方式由公司規範決定。

新增同樣品測次判定留白，不複製上次數值或照片，不自動Save；原測試結果、抽樣方案及必要複驗對象保持唯讀。無法取得原件、破壞試驗、挑選／返工後重新抽樣需填原因及新樣品身分，沿另行確認的複驗計畫，不把新件冒充原件。

一般補測、二次抽樣及異常後複驗是不同情境。若正式方案是二次抽樣，必須保留第一階段結果與累計判定；不能讓一般「再測一次」按鈕暗中變成二次抽樣方案或重新開始計數。

FQC目前每項100結果列的限制不能直接當IQC抽樣上限。需依實際n決定逐件資料、分頁／批量輸入或受控彙總；不能為適應畫面減少應抽件數。

## 狀態與審核條件草案

建議流程：進料批待確認 → 工作待安排 → 計畫草稿 → 計畫核准 → 初驗報告草稿 → 固定送審 → 正式檢驗結果 → 批次決策；異常另外改善／複驗／處置 → 待結案 → 明確確認結案。計畫是否每批先審、批次決策是否另送審，分別見C03與C08。

| 動作或狀態 | 沿用的固定機制 | IQC建議業務條件，待確認 |
| --- | --- | --- |
| 建立工作 | 正式來源、穩定ID、防重複、CAS與收據 | 批身分、實際供應商、零件、批量／單位與可執行規則足夠；缺資訊列待確認 |
| 建計畫／報告 | 所選工作合法且未被其他文件占用 | 一批一份報告；初驗只建一次，既有草稿直接接續 |
| Save | 手動固定整份文件，不受搜尋／分類縮小 | 未完成內容可留草稿；非法引用、數量格式、樣品ID衝突或來源改寫拒絕 |
| Submit | 僅取最後成功手動Save，不代存；固定案件並鎖該文件 | 要求可追溯批次、完整方案與必要結果；是否准許「檢查未完成報告」另見C06 |
| Approve | 權限、案件仍有效、正式基底與revision一致 | 核准留存完整失敗報告可以，不能要求先改成合格；不得自動當放行 |
| Return／Withdraw | 固定案件歷史保留，解鎖原文件而非另建副本 | 理由與自審政策由C07定案；保留最新權限，不新增一般員工核准權 |
| 單件合格 | 保存實際證據 | 目視是否用符合描述、量測是否需值＋單位；不能所有項目硬填數字 |
| 單件不合格 | 保留原失敗、原因與可追溯證據 | 必填說明；是否一張照片或可接受其他附件由C06決定 |
| 無法測試 | 不造樣品／量測結果 | 填原因，標未完成；批量／方案即使已填，也不能冒充已完成抽樣 |
| 已測但無法判定 | 保留實測及原因 | 判定缺口、附件、補判／複驗要求由C06定案 |
| 項目抽樣接受 | 正式結果與方案留存 | 抽樣數足夠、依確認界線計算；其中有缺陷仍保留單件失敗 |
| 整批決策 | 保留決策人、時間、固定依據 | 接受／拒收／待判定／特採／退貨等種類、必要項目與權限由C08、C09定案 |
| 確認異常結案 | 改善／歷次報告、權限及明確結案紀錄 | 原件驗證、重新抽驗或處置的閉環方式不能只靠改狀態 |
| 取消／復原 | 軟取消、歷史、相依、占用與待審保護 | 批次撤銷／數量變更不得抹掉正式報告或搶回另行安排工作 |

IQC主檔目前缺少業務內容可作非阻擋待補，非法已填格式／引用仍阻擋；這不等於新批次報告缺抽樣證據也可標接受。建議在執行頁分清「可留存未完成報告」與「不可形成接受決策」。審核者可以核准一份真實不合格／未完成紀錄，卻不能透過核准把缺漏變成合格。是否採此兩層方式是C06的必要確認。

## 需要使用者確認的條件

以下建議值是討論起點，未回答不表示同意；不重問已定的清單布局、Save／Submit和CAS機制。

| 編號 | 要確認的決定 | 建議起點 | 影響 |
| --- | --- | --- | --- |
| C01 | 進料批從哪裡來，必填哪些欄位，同批分次到貨怎麼識別；批次截止日如何算 | 第一版手動建立受控批紀錄，零件、實際供應商、內部批ID、數量單位、到貨日必填；截止日明填，暫不接ERP | 防混批、逾期與重複工作 |
| C02 | 工作是否同時有時間／批次，多條規則如何適用，計畫能否跨批 | 兩類工作同頁分開；一報告一批；規則逐條保留，不把時間結果替代每批檢查 | 排程、來源ID、計畫範圍 |
| C03 | 每批計畫先審再測，或依已核准標準直接填報 | 第一版沿用FQC先核准計畫；若現場要求快速進料，另定可重用標準計畫及偏離重審條件 | 日常步驟與計畫審核量 |
| C04 | AQL正式依據／版本、檢驗水準與方案；固定件數的接受界線；批次數量欄的意思 | 用公司已採用表，不自行預設；規則不完整列待確認，無自動判定 | 抽樣數、Ac／Re、計算與版本 |
| C05 | 不合格品與缺陷如何計數；缺陷等級；樣品失败但批次接受是否仍開異常 | 計數單位明確；樣品失敗不可覆寫；異常門檻按公司政策，重大缺陷是否拒收另定 | 是否與FQC失敗聚合分開 |
| C06 | 每種結果的值、說明、照片／附件要求；不足樣本或未判定可否送審 | 完整結果正常送審；未完成紀錄可另送審留存但保持待補，不得產生批次接受；證據要求按結果明訂 | 哪些缺漏阻擋哪個動作 |
| C07 | 計畫／報告／免驗／處置由誰核准；自審、發回及撤回理由 | 沿現有模組／動作權限，職務另指派；自審必須明確確認，ADMIN-only或既有審核者由你選；發回／撤回填原因 | 不能直接照搬FQC理由例外 |
| C08 | 報告核准是否已可整批接受，是否另設批次決策；工作何時完成、誰可放行 | 分開檢驗完成與批次決策；第一版只記系統內決策，不改庫存、不對ERP放行 | 批次接受與庫存操作界線 |
| C09 | 免驗、特採、退貨、報廢、返工哪些需要；必要原因／附件／權限及是否仍標失敗 | 先做拒收後改善複驗／退貨處置；不預設特採或永久免驗；免驗永不等於合格 | 商業處置與異常結案 |

C01、C04、C06、C07、C08會直接決定批次送審與接受條件，宜先確認。其餘可隨同一批實例完成差異表。確認後才將決定寫進正式IQC例行規格；批准這份規劃也不自動授權資料移轉或部署。

## 分階段建議與驗收清單

第一階段先用一個具正式規則的零件、一個供應商、兩個獨立批次做差異確認，使用虛構例子，不建立實際測試資料。若要先縮小範圍，可先決定固定件數的判定，再引入公司AQL表；主檔已有AQL的項目仍顯示待確認，不用固定件數偷換。

後續取得實作授權才抽出共用清單／文稿／審核與來源政策介面，保留FQC相容性，加入IQC時間和批次來源。再做異常、複驗、免驗／處置和批次決策；ERP、庫存封鎖及供應商自動加嚴另列範圍。

| 驗收方向 | 後續要證明的條件 |
| --- | --- |
| 批次識別 | 同件不同批／供應商不混合，同批分次到貨依政策，重試或雙人建立不重複 |
| 來源與規則 | 只用正式啟用來源；多規則／無法解析列待確認；改版不回寫舊報告 |
| 抽樣數 | 同一件多次結果只算一件；跨項目各算；不合格品與缺陷不混數，未測不當合格 |
| 判定邊界 | 確認表的接受／拒收臨界、樣本不足、小批、錯誤批量、分階段與重新抽樣 |
| 文稿 | 缺漏可存，Submit用最後Save；兩批草稿互不影響；固定案件不能被新輸入替換 |
| 審核 | 入口平台同案、權限／自審／發回撤回理由、待審鎖、失效案件／並行衝突 |
| 異常與決策 | 失敗可正常核准留存；接受不抹失敗；特採／退貨不變合格；新批合格不關舊案 |

| 保全與相容 | FQC、IQC主檔、照片、權限、歷史與其他模組不被覆蓋；未知回應查收據 |
